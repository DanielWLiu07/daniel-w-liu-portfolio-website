## Covered shader compilation (September 15, 2026)

`compile-scene.ts` retains Three r185's sequential node construction and cooperative yields, but overlaps up to eight GPU pipeline promises with a sliding window. It drains every job before returning and restores the backend method, including on failure. Only covered precompilation uses this adapter; ordinary rendering is unchanged. Other Three revisions and WebGL use the stock compiler. Revalidate the adapter when upgrading Three; r185 contains the shared pipeline-descriptor reset fix: https://github.com/mrdoob/three.js/pull/33794.

The full covered compositor render and GPU readback fence remain mandatory. Removing the separate precompile was tested and rejected: more main-thread blocking and a late pipeline after reveal.

Matched local production-build stress tests, three fresh Chrome profiles per version: original ready times 8.84/8.61/8.45 seconds; eight-job window 6.73/5.88/6.31 seconds. Median 8.61→6.31 seconds (27% reduction). These are controlled compilation tests, not deployed timings or a guarantee for Safari/phones. The harness disables browser HTTP/shader disk caches and Dawn blob caching, renames shader entry points, and adds a per-run sub-millionth clip-space vertex offset to force fresh vertex compilation without materially changing the image. This perturbation exists ONLY in the browser test harness, never website code; it does not reset every OS/driver cache or invalidate every fragment shader. Plain fresh-profile repeats cannot establish a true cold-GPU speedup on their own.

Regression checks: `npx tsx scripts/check-compile-scene.ts`, `npx tsx scripts/check-scene-warmup.ts`, `npx tsx scripts/check-casino-intro-ready.ts`, and `npx tsx scripts/check-card-render-layers.ts`. Browser checks must also watch for GPU validation errors and new pipeline creation throughout the full intro, not just successful loading.

### All-pass preflight follow-up

`compile-passes.ts` now discovers pipeline variants by walking the real covered render path first. During that synchronous discovery only, drawing is suppressed and backend pipeline creation uses asynchronous promises. Methods are restored before yielding and every submitted job is drained even on failure. This first phase lets the browser schedule compilation across all required passes; unlike the colour compiler's eight-job window, discovery submits the finite pass set together. It is guarded to Three r185 WebGPU, with the ordinary colour compiler/full-render path retained for other backends/revisions.

After discovery, a colour-only compile collects variants not used by that pass configuration. Omitting this step caused a late pipeline and was rejected. A full real render, position invalidation, GPU readback, and restored-state frame are still required before the intro. No images, scene quality, models, or animation timing changed. Native CSS handles the loading spinner (and respects reduced motion); CPU-heavy shader construction no longer directly drives its transform through rAF.

Fresh-vertex compilation stress tests on local production builds: 5.89/5.29/5.36 seconds, median5.36 versus previous6.31 (~15% lower). Two full desktop stress-test intros had zero late pipelines, >50ms frames, or long tasks. Ordinary fresh-profile desktop ready2.60s. These still have the cache limitations described above and are not Safari/device guarantees. Preflight concentrates more CPU construction under the cover (~1.9–2.1 seconds of aggregate long tasks versus~0.7 previously); the tradeoff is shorter total preparation, not less CPU work. Add `npx tsx scripts/check-compile-passes.ts` to the regression checks.
## Optimized upper-body delivery and comparison

`/resume/compare` shows the production model beside an experimental 930,416-byte GLB, with synchronized orbit/zoom, matched lighting, close-up presets, expressions, motion, and wireframe. The résumé now selects this optimized upper-body model when its source manifest matches; the older compressed versions remain fallbacks after a source rebuild.

Rebuild the experiment with `node scripts/build-dealer-1mb.mjs .3` followed by `node scripts/compress-casino-dealer.mjs --experiment --precision`. This removes vertices using meshoptimizer's attribute-aware simplifier (normal and UV weights), reducing 65,958 triangles to 17,620, and resizes the embedded texture to 1024px WebP75. Both hands retain every authored triangle. Thirty small, closed, rigidly skinned joint connectors bridge spaces between the original phalange pieces without adding materials or draw calls. The original hand surfaces are closed meshes; restoring their triangles alone did not fill these inter-segment spaces. Trousers and both shoes are omitted while their transform nodes and the skeleton are retained. Surviving vertices retain their skin weights and morph deltas; the skeleton, expression channels, and animation data are retained. Intermediate experiment files are ignored; only the `-1mb.glb` and its manifest are shipped. This is an intentionally lossy prototype: silhouette, shading, texture detail and deformation can differ, especially up close. It is the selected résumé delivery model; browser scene checks remain necessary after regeneration.

`node scripts/check-dealer-1mb.mjs` checks the size cap, shipped decoder, indices, skeleton, transforms, animation data and every expression's skinned vertex path. Browser comparison should include face/hand close-ups and a normal-size portrait. The comparison uses neutral studio lighting rather than the casino compositor, and loading two models together is not a performance benchmark.

Research (September 2026): [Three.js optimization guidance](https://threejs.org/manual/en/optimize-lots-of-objects.html) explains the cost of meshes/draw requests and scene nodes. [Khronos asset guidelines v2](https://github.com/KhronosGroup/3DC-Asset-Creation/blob/main/asset-creation-guidelines/RealtimeAssetCreationGuidelines.md) describe balancing geometry detail, delivery size, materials, and texture cost. A 17.6k-triangle model is not itself evidence of a performance bottleneck; frame-time measurements in the complete casino scene on target devices are needed. This studio comparison does not establish mobile performance.

Clothing refinement: the shirt and waistcoat now use a separate 8% target with locked borders and skin-weight attributes in the simplification metric. Error limits (.004 for the shirt, .008 for the waistcoat) stop reduction before the target where detail is needed. Other retained parts, including face geometry and repaired hands, keep their prior settings. This constrained edge-collapse pass reduces the candidate from 22,681 to 17,620 triangles and from 1,005,768 to 930,416 bytes; it is not a manual quad retopology. Run `node scripts/check-dealer-clothing.mjs` for a bidirectional sampled surface-distance check against the authored clothing in three arm/spine poses (20,709 sampled vertices, maximum observed deviation 4.01 mm, 6 mm guardrail). This is a sampled check, not a mathematical bound for all animation poses.
